# Техническое задание на разработку веб-приложения для анализа отзывов

## 1. Назначение проекта

Необходимо разработать веб-приложение на Python для анализа пользовательских отзывов маркетплейса. Приложение должно позволять пользователю загружать CSV/XLSX-файл с отзывами, выполнять предварительную обработку текста, определять аспекты и тональность отзывов, отображать результаты в таблицах и аналитических графиках, а также экспортировать итоговые данные.

Приложение разрабатывается как часть ВКР на тему:

> «Разработка системы анализа тональности пользовательских отзывов на маркетплейсе с использованием нейронных сетей».

Основной пользователь приложения — селлер или аналитик маркетплейса.

## 4. Входные данные

Пользователь загружает CSV или XLSX-файл с отзывами.

Поддерживаемые поля:

| Поле | Обязательность | Описание |
|---|---|---|
| `review_id` | необязательное | идентификатор отзыва |
| `product_name` | необязательное | название товара |
| `rating` | необязательное | числовая оценка пользователя |
| `review_text` | обязательное | текст отзыва |
| `date` | необязательное | дата публикации отзыва |

Если `review_id` отсутствует, система должна автоматически создать его на основе порядкового номера строки.

Если `review_text` отсутствует, приложение должно показать ошибку и не запускать анализ.

Если часть строк содержит пустой `review_text`, такие строки должны быть помечены как некорректные и исключены из анализа.

## 5. Аспектная схема

Использовать 4 аспекта:

```text
Качество товара
Соответствие описанию
Упаковка
Доставка
```

Для каждого найденного аспекта определить тональность:

```text
positive
negative
neutral
```

В интерфейсе можно отображать русские подписи:

```text
Положительная
Отрицательная
Нейтральная
```

Один отзыв может содержать несколько аспектов. Поэтому итоговая таблица результатов должна иметь связь «один-ко-многим»:

```text
один отзыв → несколько строк результата по аспектам
```

Пример:

| review_id | review_text | aspect | sentiment |
|---|---|---|---|
| 1 | Товар хороший, но упаковка мятая | Качество товара | positive |
| 1 | Товар хороший, но упаковка мятая | Упаковка | negative |

## 6. Реализация модуля анализа

В файле `modules/analyzer.py` реализовать класс или функции для анализа отзывов.

Важно: приложение должно быть готово к подключению нейросетевой модели RuBERT через `transformers` и `torch`.

На первом этапе, чтобы приложение можно было запустить без обученного чекпойнта, реализовать fallback-режим на правилах.

Требования к `analyzer.py`:

1. Создать функцию:

```python
analyze_reviews(df: pd.DataFrame, text_column: str = "processed_text") -> pd.DataFrame
```

2. Функция должна возвращать таблицу с полями:

```text
review_id
date
review_text
processed_text
aspect
sentiment
confidence
```

3. Если в отзыве найдено несколько аспектов, вернуть несколько строк.

4. Если аспект не найден явно, можно вернуть строку:

```text
aspect = "Общее впечатление"
sentiment = neutral / positive / negative
```

Лучше по возможности определять один из четырех заданных аспектов.

5. Использовать простой rule-based fallback.

Пример словарей:

```python
ASPECT_KEYWORDS = {
    "Качество товара": ["качество", "сломался", "брак", "материал", "работает", "не работает", "хороший", "плохой"],
    "Соответствие описанию": ["описание", "соответствует", "не соответствует", "как на фото", "цвет", "размер"],
    "Упаковка": ["упаковка", "коробка", "пакет", "помята", "повреждена", "упаковано"],
    "Доставка": ["доставка", "курьер", "привезли", "задержка", "быстро", "долго"]
}
```

Слова для тональности:

```python
POSITIVE_WORDS = ["хороший", "отличный", "понравился", "быстро", "качественный", "удобный", "супер", "рекомендую"]
NEGATIVE_WORDS = ["плохой", "ужасный", "сломался", "брак", "мятый", "поврежден", "долго", "не работает", "не соответствует"]
```

6. `confidence` в rule-based режиме можно задавать условно:

```text
0.90 — если найдены аспектные слова и слова тональности
0.75 — если найден аспект, но тональность слабая
0.60 — если определена только общая тональность
```

7. В коде оставить отдельное место для подключения RuBERT:

```python
# TODO: replace rule-based fallback with fine-tuned RuBERT model inference
```

И функцию-заготовку:

```python
load_model()
```

Функция не должна ломать приложение, если модель не подключена.

Важно: в интерфейсе не писать, что используется полноценная обученная нейросеть, если фактически работает rule-based fallback. Можно указать нейтрально:

```text
Модуль анализа отзывов
```

## 7. Предобработка текста

В `modules/preprocessing.py` реализовать функцию:

```python
preprocess_reviews(df: pd.DataFrame, text_column: str = "review_text") -> pd.DataFrame
```

Она должна:

1. Скопировать исходный датафрейм.
2. Создать поле `processed_text`.
3. Создать поле `is_valid`.
4. Создать поле `error_message`.
5. Очистить текст:
   - привести к строке;
   - убрать лишние пробелы;
   - убрать управляющие символы;
   - не удалять отрицания;
   - не удалять эмоционально значимые слова.
6. Пустые отзывы пометить:

```text
is_valid = False
error_message = "Пустой текст отзыва"
```

7. Непустые отзывы пометить:

```text
is_valid = True
error_message = ""
```

## 9. Агрегация результатов

В `modules/aggregation.py` реализовать:

```python
aggregate_results(results_df: pd.DataFrame) -> pd.DataFrame
```

Агрегированная таблица должна содержать:

```text
aspect
mention_count
positive_count
negative_count
neutral_count
confidence_avg
```

Требования:

1. `mention_count` — количество строк по аспекту.
2. `positive_count` — число `positive`.
3. `negative_count` — число `negative`.
4. `neutral_count` — число `neutral`.
5. `confidence_avg` — среднее значение `confidence` по аспекту.
6. Доли тональностей можно считать в `visualization.py`, а не хранить в агрегированной таблице.

## 12. Интерфейс Streamlit

В `app.py` реализовать интерфейс.

### 12.1 Верхняя часть

Название:

```text
Система анализа тональности отзывов маркетплейса
```

Краткое описание:

```text
Приложение предназначено для загрузки отзывов, определения аспектов и тональности, построения аналитики и выгрузки результатов.
```

### 12.2 Загрузка файла

Добавить:

```python
st.file_uploader("Загрузите CSV или XLSX-файл с отзывами", type=["csv", "xlsx"])
```

После загрузки:

- показать количество строк;
- показать первые строки таблицы;
- показать список найденных столбцов;
- проверить наличие `review_text`.

### 12.3 Выбор текстового столбца

По умолчанию использовать `review_text`.

Если пользователь хочет, разрешить выбрать другой текстовый столбец из списка.

### 12.4 Запуск анализа

Кнопка:

```text
Запустить анализ
```

После нажатия:

1. выполнить предобработку;
2. исключить невалидные строки;
3. выполнить анализ;
4. агрегировать результаты;
5. сохранить в `st.session_state`:
   - `raw_df`
   - `processed_df`
   - `results_df`
   - `agg_df`

### 12.5 Отображение результатов

После анализа показать вкладки:

```text
Обзор
Результаты по отзывам
Дашборд
Экспорт
```

Во вкладке **Обзор**:

- всего отзывов;
- валидных отзывов;
- найдено аспектных упоминаний;
- количество отзывов с ошибками.

Во вкладке **Результаты по отзывам**:

- таблица `results_df`;
- фильтр по аспекту;
- фильтр по тональности.

Во вкладке **Дашборд**:

- график количества упоминаний аспектов;
- график распределения тональности;
- график средней уверенности модели.

Во вкладке **Экспорт**:

- кнопка скачать CSV;
- кнопка скачать XLSX.

## 14. Обработка ошибок

Приложение должно корректно обрабатывать:

1. файл не загружен;
2. неподдерживаемый формат файла;
3. отсутствует текстовый столбец;
4. все отзывы пустые;
5. ошибка чтения CSV из-за кодировки;
6. ошибка формирования XLSX;
7. отсутствие результатов перед экспортом.

Ошибки показывать через:

```python
st.error()
st.warning()
st.info()
```

## 18. Критерии готовности
